# 织图

把好奇心织成一张地图。

一个陪自学者探索的桌面软件：你随便聊、随便跑偏，它在旁边悄悄把学过的东西记成一张带结构的地图。

## 给使用者：怎么用

### 第一次打开

1. 选一个 AI 服务商（默认 DeepSeek，便宜且国内直连）
2. 粘贴你的 API Key（[点这里申请](https://platform.deepseek.com/api_keys)）
3. 点「测试连接」，看到"✓ 连接成功"就说明通了
4. 点「开始使用」，在开始卡片上输入领域或选一个现成问题

**API Key 保存在你自己这台电脑上；连接 AI 时会发送给你选的服务商。**
对话内容会发给你选的那家 AI 服务商，费用由你的账号承担。

### 日常使用

- 中间输入框打字，**Enter 发送，Shift+Enter 换行**
- 新的一场先显示开始卡片；输入领域可让 AI 挑三个起点，也可直接点示例问题
- 对话结束后等几秒看右侧笔记；每条可改、删，设置里可以重算本场笔记
  （「重算（保留现有卡片）」只刷新内容，「重算并允许重新分卡」才让模型重新决定结构）
- 点「今天到这儿」可生成本场小结；右侧未收线最多显示五条，更多内容点「全部」
- 点输入框旁的「添加资料」、拖入文件，或在输入框里粘贴图片。资料默认只在本场有效；已被对话引用的原件不能彻底删除
- 图片和扫描 PDF 需要在设置中主动开启视觉识别，可能增加 API 费用；PPT 目前只提取文字
- 左上角「＋ 新的一场」开始新的一段学习
- 左下角「⚙ 设置」随时换服务商、换模型、重填密钥
- 左栏「复习」会从到期笔记生成应用题；「搜索」可找对话、笔记与资料；「导出」可保存笔记、单场对话或全部数据备份
- 左栏「最近的学习」可回到旧场次；未收线有独立页面；系统深色模式会自动生效
- 「查看学习记录」里可以改名、归档（收起来不删数据）、删除。**删除分两级**：默认「移入回收站」，30 天内可以恢复，
  删完顶部会出现一条 10 秒的「撤销」；「彻底删除」才是不可逆的那条路，需要亲手输入"删除"两个字。
  两级都会先告诉你**会删掉什么、会留下什么**：别的场次还在用的知识点会留下，只断开与本场的连线。
  回收站里能看到占用和自动清理时间，也可以一键清空
- 对话可切换「引导 / 自由」；设置里可选择讲解深度。长期使用后，系统只在有足够信号时调整讲解深度
- 对话顶部可进入专注阅读；左栏「本周回顾」显示本周场次、笔记和未收线问题

### 你的数据在哪

打开「⚙ 设置」，最下面会显示**数据目录**。所有内容都在那个文件夹里，
核心是 `zhitu.db`。**想备份请先退出软件，再复制整个数据文件夹。**

卸载软件不会删除数据（方便你以后重装）。想彻底清掉，手动删掉那个文件夹即可。

### 常见问题

**"密钥无效或已过期"**
去设置里重新粘贴一次，注意不要带空格。确认服务商选对了。

**"账户余额不足"**
去服务商控制台充值。日常学习一天大概几毛到几块钱。

**"连不上服务器"**
检查网络。如果你在公司网络里，可能需要设代理（这一项还没做，见下）。

**"接口地址或模型名不对"**
设置里换一个模型试试。某些服务商的部分模型需要单独开通。

**窗口打不开 / 一闪就没**
打开数据目录旁边的 `logs\app.log`，里面记录了出错原因。

## 给开发者：怎么跑起来

### 环境

- Node.js 22.13 以上（开发用的是 24；PDF 解析库有此要求）
- **不需要 Visual Studio 编译工具**：`better-sqlite3` 自带全平台预编译文件

### 安装与运行

```bash
npm install          # 装依赖
npm run dev          # 开发模式（带热更新）
npm run build        # 只构建，不打商店
npm run typecheck    # 类型检查
npm run smoke        # 地基自检：在真实 Electron 里验 7 项
npm run dist         # 打包成 Windows 安装包（输出到 release/）
```

验证（推荐每次改动后都跑一遍）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify.ps1
```

会真的启动程序三次：走完首次向导、对话和资料路径（用本机假 AI 服务，不联网不花钱）、重新打开确认数据还在、打开窗口检查开始卡片与资料入口。脚本要求每阶段的检查项数量与预期一致。

> **验证脚本跑在沙箱目录里，不会碰你的真实数据。**
> 它通过 `ZHITU_DATA_DIR` 环境变量把数据目录指到每次新建的 `%TEMP%\zhitu-verify-<随机标识>`，
> 并且有两道断言守着这件事：一旦发现自己在真实目录上运行就立刻失败；脚本还会对比真实数据库的前后哈希。
> 早期版本没做这个隔离，**把用户配好的密钥和聊天记录冲掉过**，所以这条不能省。
>
> 跑完可以自己核对一下真实数据没被动过：
>
> ```powershell
> Get-FileHash "$env:APPDATA\zhitu\zhitu.db"
> ```

想把界面截成图片看，跑 `& "node_modules\electron\dist\electron.exe" "scripts\screenshot.cjs"`，图片在 `%TEMP%\zhitu-shots`。截图脚本使用独立临时数据目录和本机假 AI。

还有一个需要联网的检查（**会花掉极少量的 API 费用**），用来验证提示词在真实模型上真的生效：

```bash
npm run prompt-check
```

它只读本机已保存的加密密钥，向真实 DeepSeek 发三个对话问题，并检查领域入口、笔记抽取、冲突核对和归航提示词。自动化假模型只能证明调用链跑通；真实模型检查能暴露提示词效果问题，但不能保证所有学习内容都正确。脚本会报告 token 用量，金额需按服务商当时费率估算。

另有四组按需检查（同样花极少量费用）：

```bash
npm run prompt-check -- --review-only    # 复习出题与判题 2 项
npm run prompt-check -- --profile-only   # 学习行为信号 2 项
npm run prompt-check -- --homeward-only  # 只看归航提示词
npm run prompt-check -- --self-test-inspect   # 不联网，只验长度判定边界
```

### 回答长度的判定线

提示词里写的是"整条回答不超过 200 字"，但模型没法可靠地数字数。实测 9 个样本：
均值 180 字、中位数 196 字、最大 219 字。所以 `prompt-check.cjs` 按 **220 字**判定，
而不是按 200——按 200 卡会有三分之一因为超几个字被判失败，那是把统计噪声当成缺陷。
220 以上（实测 250+ 那种）才是真正需要拦的啰嗦。

这条例子的由来：v0.9.2 用真实模型验证时发现 3 个问题里 2 个超限（203、210 字），
追下去发现是**默认的引导模式要求每条回答末尾都附一句下一步建议**，
而那句建议也占字数——原来的提示词没把这一点算进预算。
现在的写法是"整条回答——包括最后那句建议——总共不超过 200 字"，
实测均值从 228 降到 180。

### 提示词的排版要求

`src/main/core/prompts.ts` 的共享 `FORMAT_RULES` 有三条硬性排版要求，来自使用者的明确要求：不许用符号列表，日常讲解要写成连贯段落、分点用"第一…然后…最后"连接，只有真正的操作步骤才用编号，同时禁止套话。

**改提示词时注意**：提示词本身也要写成段落，不能用符号列表；新增提示词必须拼入共享排版规则。`scripts/prompt-check.cjs` 会直接读取这份共享提示词。

### 三个必须知道的坑

**① npm 12 默认禁止第三方包运行安装脚本**

而 Electron 正是靠安装脚本下载它那 110MB 的可执行文件。如果 `npm install` 之后报
`Electron failed to install correctly`：

```bash
npm install-scripts approve --all   # 放行安装脚本
npm install                          # 重新装一次
```

`scripts/postinstall.cjs` 也会自动检查并补下载。

**② Electron 从 GitHub 下载经常断在半路**

走国内镜像，实测从"卡死在 21.5MB"变成 7 秒下完：

```powershell
$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
npm install
```

（不要写进 `.npmrc`，npm 12 不认识这两个键，会刷一堆 warning。）

**③ 不需要 Visual Studio 编译工具**

`better-sqlite3` 和 PDF 页面渲染使用的画布模块都带预编译文件，
**不需要重新编译**。所以：

- 打包配置里写了 `npmRebuild: false`，关掉 electron-builder 的重建步骤
- `asarUnpack` 里带上了 `better-sqlite3` 和画布模块，确保原生文件被解包出来

如果哪天打包报 `Could not find any Visual Studio installation`，
八成是有人把 `npmRebuild: false` 删了。

**另外：依赖若触发 `node-gyp` 本地编译，带空格或中文的路径可能出错。**
本项目使用预编译原生模块，当前仓库路径包含空格和中文，已在此路径成功完成构建与打包。

### 安装包模式说明

`electron-builder.yml` 里 `nsis.oneClick` 决定了安装体验：

| 值 | 行为 | 适用 |
|---|---|---|
| `false`（当前） | 显示向导，**允许用户选安装目录** | 用户想控制装到哪 |
| `true` | 双击即装，不问任何问题，装到 `%LOCALAPPDATA%\Programs\<名>` | 完全不懂电脑的人最省事 |

两种模式都支持静默安装。下面是重新运行 `npm run dist` 后的示例：

```powershell
# /S 静默安装，/D= 指定目录（必须是最后一个参数，路径不能加引号）
& "release\织图-安装包-0.9.2.exe" /S /D=E:\some\dir
```

> **注意**：`/D=` 是安装到指定目录，但程序名固定，所以
> **在同一台机器上装到第二个目录，两个副本会共用同一个卸载程序**
> （都记在 `%LOCALAPPDATA%\Programs\<名>` 那个注册项上）。
> 卸载任何一个都会把默认位置那份一起清掉 —— 做安装测试时要注意这一点。

### 更新约定（每版都照这个来）

**先卸旧、再装新，只留一份。**

```powershell
# 1) 卸载旧版（静默）。卸载程序在安装目录里，也可以从注册表查 UninstallString
& "$env:LOCALAPPDATA\Programs\zhitu\Uninstall 织图.exe" /currentuser /S

# 2) 装新版（静默）。不带 /D= 就装到默认位置
& "织图-安装包-<版本>.exe" /S
```

三条必须记住的：

1. **绝对不要把程序装进源码目录**（比如 `zhitu\release`）。NSIS 卸载器会把自己登记的整个安装目录删掉——
   2026-09-30 那次就是把 `release\` 连同 `win-unpacked\` 一起删了，还好安装包事先复制到了交付目录。
2. `release\` 只是**构建输出**，不是安装目标，也不该当成"免安装版"长期使用：装到第二个目录会出现
   "两个副本共用一个卸载程序"的问题（见上面的注意）。
3. **静默安装不会自动启动程序**，装完自己双击快捷方式即可；桌面和开始菜单的快捷方式指向
   `%LOCALAPPDATA%\Programs\zhitu\织图.exe`。
4. 卸载**不会删数据**（`deleteAppDataOnUninstall: false`），`%APPDATA%\zhitu` 原样保留；
   升级数据库之前先复制一份 `zhitu.db` 出来。

### 目录结构

```
src/
├─ main/                    ← 主进程（后端）
│  ├─ index.ts              ← 启动流程：开数据库 → 起本地服务 → 开窗口
│  ├─ server.ts             ← 本地 HTTP 接口
│  ├─ log.ts                ← 日志（写到 数据目录/logs/app.log）
│  └─ core/
│     ├─ db.ts              ← 建表语句、数据库连接
│     ├─ settings.ts        ← 设置读写 + 密钥加密（safeStorage）
│     ├─ store.ts           ← 对话流水、学习场次
```

### 几个刻意的设计决定

1. **界面不通过 IPC 拿数据，而是走本地 HTTP。**
   本地服务监听 `127.0.0.1` 的**随机端口**，带一个每次启动都不同的凭证。
   好处是主进程、数据、界面三者解耦——以后想把后端拆成独立进程（比如换 Tauri）
   几乎是机械劳动。

2. **`turns` 表只追加，永远不修改。**
   它是"原件"，以后所有的笔记、地图都是从它派生出来的。
   抽取失败、换模型重算，都不会破坏已有数据。

3. **所有服务商都走 OpenAI 兼容协议。**
   加一家新服务商 = 在 `src/shared/providers.ts` 里加一行。

4. **密钥用 Electron 的 `safeStorage` 加密后落盘**（Windows 走系统 DPAPI）。
   不可用时才退回明文，并且界面会如实提示用户。

5. **数据和代码分开。** 数据库在系统的用户数据目录，不在安装目录——
   否则卸载或更新时会丢数据，而且 Program Files 本来也没有写权限。
