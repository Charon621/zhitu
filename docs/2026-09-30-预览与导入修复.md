# 2026-09-30 预览与导入修复

这份记录对应一次源码修复，**没有改版本号**（仍是 `package.json:0.10.0`），因为当时 `release\织图.exe` 正在运行、文件被占用，没有重新打包。

## 修了什么

### 1. 「查看原件」的图片和 PDF 根本显示不出来（最严重）

**现象**：资料库选一份图片或扫描 PDF 点「查看原件」，只看到空白；对话页的资料预览同样。

**根因**：预览走的是 `URL.createObjectURL()` 生成的 `blob:` 地址，而页面 CSP（`src/renderer/index.html:8`）只写了 `img-src 'self' data:`，没有 `blob:`。Chromium 不认为 `blob:` 匹配 `'self'`。实测报错：

```
Refused to load the image 'blob:file:///…' because it violates
the following Content Security Policy directive: "img-src 'self' data:".
Refused to frame 'blob:file:///…' …（frame-src 未设置，回退到 default-src）
```

**影响范围**：资料库「查看原件」（图片 / PDF）、对话页的资料预览（`Chat.tsx:1041-1044`）。后者是 v0.9 就有的路径，所以这是**存量缺陷**，不是 v0.10.0 引入的。文字资料预览走 `<pre>`，不受影响——这也是它一直没被发现的原因：所有验收脚本都是用文件选择框注入 + 接口断言，从来没有真正渲染过一张 blob 图片。

**改动**：`src/renderer/index.html:8` 的 CSP 加上 `blob:`：

```
img-src 'self' data: blob:; frame-src 'self' blob:;
```

**新增验收**：`scripts/library-ui.cjs` 加了一条「图片原件能真正渲染出来」——点「查看原件」后断言 `<img>` 已加载且 `naturalWidth > 0`。修复前这条必红。

### 2. 拖拽导入会做两遍，并把用户从资料库拽回对话页

**现象**：把文件拖到资料库页面，文件被上传两次（资料库一份、对话附件一份），页面跳回「对话」。

**根因**：资料库的落点只 `preventDefault()`，没有 `stopPropagation()`（`LibraryPage.tsx:158-160`），事件继续冒泡到外层 `<main>` 的 `onDrop`（`Chat.tsx:682-685`，`LibraryPage` 就渲染在这个 main 里，`Chat.tsx:697`），对话侧的 `importFiles` 第一件事是 `setPage('chat')`（`Chat.tsx:354`）。

**改动**：资料库 `onDrop` 加 `e.stopPropagation()`。

### 3. 刚导入的书会沿用上一次的整理方式

**现象**：第一次打开资料库就拖进一本 PDF，界面按「手写笔记」规划，整本书的页数都被算作视觉识别页（`library.ts:83-84`），按钮还写着「开始识别并分类」。

**根因**：`importFiles` 只设 `selected` 和页码，不设 `mode`（`LibraryPage.tsx:90-106`），而 `mode` 初值是 `handwriting`（`LibraryPage.tsx:19`）。

**改动**：加了一个 `inferMode` ref——拖入和页头「导入资料」按文件类型推断（图片→手写，其余→书籍）；走「01 / 手写笔记」「02 / 书籍阅读」入口进来的不覆盖用户的选择（扫描 PDF 也常走手写识别，不能被类型推断改掉）。

### 4. 在 Electron 系终端里跑验收会整体失败

**现象**：`verify.ps1` 报 `Phase 1 FAILED (exit=1, checks=0/162)`，应用根本没起来，报 `TypeError: Cannot read properties of undefined (reading 'setName')`。

**根因**：这类终端（例如 DSH）会导出 `ELECTRON_RUN_AS_NODE=1`，子进程里的 Electron 会退化成纯 Node，`require('electron')` 拿到的不再是主进程模块。

**改动**：`scripts/verify.ps1` 开头清掉这个环境变量（文件仍是纯 ASCII）。现在不管从哪种终端启动，结果都一样。
