# 织图 v0.9.2 · 场次归属与边界修复

这一轮不改界面，改的是"一个主题下有很多场学习"时系统一直没算清的一件事：
**哪些知识节点属于当前这一场。**

v0.9.1 已经让笔记抽取按场次续接，但工作集和归航还在按整个主题取节点。
结果是：回到旧场次继续聊，AI 会以为你在聊另一场的话题；对某一场点"今天到这儿"，
别的场次的未收线问题会被算进本场小结。

## 修复内容

**场次归属统一。** `Store` 新增 `currentNodeFor` / `sessionNodeIds` / `sessionNodeOrder`
三个查询，把"这个节点算不算这一场的"这件事收敛到一处，三处调用者共用：

- 工作集的【当前知识点】和【本场已经记下的笔记标题】改为按本场取。
  以前取的是主题下 `last_seen_at` 最新的节点，所以回到旧场次继续追问时，
  塞给模型的"现在聊到哪了"可能是另一场的知识点。
- 归航判定的支线改为只取本场涉及的节点。以前按 `topic_id` 全量取，
  于是结束 A 场会把 B 场的问题写进 A 场小结，还会把已经收过线的旧场次重新标成未收线。
- 回到旧场次继续追问同一个知识点时，那个点（原本创建于早先场次）仍算本场的活支线，
  收线时能收得到。

**未收线不再漏掉概念型节点。** 判定清单和收线以前都要求 `kind = 'question'`，
而节点类型是按标题形态定的：标题里没有问题词（"残差连接为什么有用"这类）会建成
`concept`。这些节点在未收线清单、本周回顾里整条消失，用户也没有任何入口收它的线。
现在清单纯粹由 `status = 'open'` 决定。

**自动归航失败可以重试。** 以前闲置自动归航失败一次就把这场标记成"试过了"，
断网一次这场就永远不再自动整理。现在失败保留重试机会（最多 5 次），
成功或用户又回来聊时才清掉标记。

**重算不再拆散本场的学习路径。** 重算会把笔记搬到新卡片上，中间那些旧节点就空了。
删掉它们时 `ON DELETE CASCADE` 会把两端的父边一起带走，本场路径整段消失
（地图上变成几个互不相连的孤点）。现在收尾时先删空节点，再按本场的实际轮次顺序
重连父边——这正是正常抽取时父边的来路。

**重算时的两处口径问题。**

- 抽取记录会在建卡时立刻改指向新节点。否则本场后面几轮读到的"本场最近节点"
  还是那个已经删掉的旧 id，它们之间的父边会因此插不进去。
- 父节点查询补回"只算更早的轮次"这个边界，避免同一轮把自己刚建好的节点
  当成"上一个知识点"，明明在补充同一个问题却每轮另起一张卡。

**重算可以保留你调好的卡片。** 设置里现在有两个入口：
「重算（保留现有卡片）」只刷新笔记内容，不改标题也不重新分卡；
「重算并允许重新分卡」才让模型重新决定。短回复合并抽取留下的占位轮次
不再被重算重复计费（结果里会报告合并了多少条）。

**模型给的卡片标题真的会生效。** 以前 `update` 分支只更新掌握度和时间，
`nodePatch.title` 被静默丢掉，用户在界面上永远看不到标题更新。

**密钥状态如实上报。** 密文还在但这台机器解不开（换过系统账户、拷过数据目录、系统重装）时，
设置页以前显示"已加密存储、一切正常"，实际每次对话都失败在"还没有填密钥"。
现在这种情况明确显示"密钥失效，请重新粘贴"。

**视觉模型名单放宽。** 名单以前把常用的多模态模型挡在外面：OpenAI 的默认
`gpt-4o-mini`、智谱的 `glm-4-plus`/`glm-4-air` 都会被判成"不支持图片"。
现在按系列匹配，用户填了明确的视觉模型时仍优先用那个。

**其他边界。** 画像信号解析失败不再抛到主进程（模型偶发返回非 JSON 时
不再有未处理拒绝）；退出时先关本地服务再关数据库；脚本模式的就绪标记
从共享临时目录挪进隔离数据目录。

**历史记录管理（本轮新增）。** 以前只有"查找和回看"，没有任何管理动作——
`store.renameSession()` 是没人调用的死代码，`topics.archived_at` 永远是空值。
现在补齐三件事：

- **改名**：学习记录里直接改。
- **归档**：新增 `sessions.archived_at`（数据库迁移到 v7）。归档只是从列表收起来，
  数据一条不动；归档当前这一场会退回开始卡片，免得停在一个已经收起来的场次里。
- **删除**：粒度是**"删对话 + 它独占的知识点"**。别的场次还在用的点会留下，
  只断开与本场的连线。删除前必须先看一次预演——会删掉多少条对话、几个知识点、
  几条笔记、几份原件，以及**哪几个知识点会留下**。删除不可逆，不能只靠一个"确定吗"。

"独占"的判定是这一块的关键：一个点必须同时满足"本场建出来的"（`origin_turn_id` 在本场轮次里）
和"没有别场抽取过它"，才会被删。少了后半句，回到旧场次追问过的知识点会被连带删掉，
那张地图就断了。删除还会清理数据库管不到的磁盘孤儿原件，以及没有场次也没有知识点的空主题。

数据库迁移这次留了个教训：往 `sessions` 加列时不能直接 `ALTER TABLE ... ADD COLUMN`——
全新数据库按 v1 建表时已经带上了这一列，再执行就会撞 `duplicate column name`。
脚本里现在有一条 v6 老库升级的专项检查守这件事。

**回答长度的提示词缺陷（真实模型验证发现）。** 用真实 DeepSeek 跑提示词检查时，
3 个问题里 2 个超出 200 字（203、210 字）。追下去发现不是模型不听话，是提示词本身有矛盾：
默认的引导模式要求每条回答末尾附一句下一步建议，而那句建议也占字数，
原来的"回答控制在 200 字以内"没把它算进预算。改成"整条回答——包括最后那句建议——
总共不超过 200 字，这是硬上限，宁可少讲一个细节，也不要超"之后，
实测 9 个样本均值从 228 字降到 180 字（中位数 196，最大 219）。

对应地，`prompt-check.cjs` 的长度判定线定在 220 字而不是 200：
模型没法可靠地数字数，按 200 卡会有三分之一因为超几个字被判失败，
那是把统计噪声当缺陷。判定边界本身有离线自检（`--self-test-inspect`）。

笔记对抗检查从 28 增到 36，新增的 8 项里 5 项是历史记录管理与数据库迁移：
删除预演分清了会删和会留、删除只带走这一场独占的知识点、删完之后别的场次仍然可用、
归档不动数据只改标记、取消归档后重新回到列表、删掉最后一场且无知识点时主题一起清理、
删光两场后共用知识点与主题都留下、v6 老库能补上归档字段。

界面检查从 135 增到 142，覆盖：每行都有管理入口、改名写回数据库、归档后从列表收起而数据仍在、
已归档可以恢复、删除前先给预演、确认后真删、删除入口是危险样式。

**截图发现的问题**：操作按钮最初写成 `opacity: 0`、只在鼠标悬停时显示。
功能是好的、自动化检查也全绿（DOM 里确实有按钮），但截图上整个功能看不见。
已改成常驻可见但压暗、指到那一行才提亮。这就是"界面改动必须截图"这条规矩的价值。

笔记对抗检查里另有 3 项专门守住场次归属这条线，
每一项都在修复前会失败：

- 工作集的当前知识点只来自本场
- 归航只判定本场的支线
- 未收线清单包含 concept 节点且不收别的场次

服务端端到端新增 3 项：密钥可用时如实报告为可用、解不开的密钥不会被谎报成可用、
原密钥恢复后重新可用。同时把两处写死"8 条对话"的断言改成与数据库实际条数比对——
原先只要别处补了测试数据，这两条就会误报。

## 边界

验证仍使用本机假模型和合成资料跑常规回归；真实模型只用于提示词效果检查（12 项），
没有跑完整的真实学习流程。"工作集的当前知识点"现在严格来自本场，
因此主题下另一场建立的知识点只有在本场重新聊到、或经全文检索召回时才会进入上下文
——这是刻意的取舍：宁可少带，也不要把别场的话题当成当前进度。

回答长度这条规则是"目标 200 字、判定 220 字"：模型做不到精确数字数，
偶尔仍会超几个字（实测最大 219 字），这属于已知误差，不再当成缺陷追。

打包程序独立启动检查 6 项通过（独立进程、版本 0.9.2、数据隔离、首次向导配置、
笔记接口、未授权读取拒绝）。安装包 Authenticode 状态为 NotSigned，
**安装程序本身仍需在独立环境里双击实测**。
