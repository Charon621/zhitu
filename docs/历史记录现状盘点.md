### 1.3 归档 vs 删除的确切语义

**归档（archive）＝ 只改一个字段，零数据变动。**
- `setArchived()` 只执行 `UPDATE sessions SET archived_at = ?`，返回 `changes === 1`：`store.ts:194-198`。
- 不触碰 `turns` / `nodes` / `edges` / `note_blocks` / `attachments` / `extractions`：由 `store.ts:193-198` 全函数体可证（函数内仅此一条 SQL）。
- 归档不改变"是否算最近一场"以外的任何查询：`latestSession()` 过滤 `archived_at IS NULL`，`store.ts:136`。
- UI 侧把归档场次从列表移除：`Chat.tsx:232-235`（`filter((item) => !item.archived_at)`）。
- **归档可逆**：`archived:false` 写回 `NULL`，`store.ts:196`。

**删除（delete）＝ 真删，两段式，不可逆。**
- 事务内按序执行：先删本场"独占"节点 → 再删 session 行 → 再按条件删空主题：`store.ts:275-288`。
  - `DELETE FROM nodes WHERE id = ?` 逐个删独占节点，`store.ts:276-277`
  - `DELETE FROM sessions WHERE id = ?`，`store.ts:278`
  - 仅当该主题下**既无 session 又无 node** 时 `DELETE FROM topics`，`store.ts:281-287`
- **会被删的行（靠 CASCADE 连锁）**：`turns`（CASCADE `db.ts:47`）→ 连带 `extractions`（`db.ts:97`）、`turn_meta`（`db.ts:139`）、`profile_observations`（`db.ts:260`）、`session_homeward`（`db.ts:234`）；`attachments`（CASCADE `db.ts:112`）→ 连带 `chunks`（`db.ts:130`）、`document_analyses`（`db.ts:324`）；独占 `nodes` → 连带 `edges`（`db.ts:84-85`）、`note_blocks`（`db.ts:147`）、`reviews`（`db.ts:170`）、`review_attempts`（`db.ts:243`）、`homeward_state`（`db.ts:224`）。
- **会留下的行**：
  - 别的场次也在用的节点：`exclusiveNodeIds` 要求 `NOT EXISTS` 别场抽取，`store.ts:213-223`；这些节点保留，只把 `nodes.origin_turn_id` 置 `NULL`（`ON DELETE SET NULL`，`db.ts:73`），即"断开与本场的连线"。
  - 主题（还有其他场次或节点时）：`store.ts:286` 的条件不成立则不删。
  - 磁盘上被其他 `attachments` 行引用的原件：删库后再查 `stored_path` 是否仍被引用，`store.ts:293-297`。
- **磁盘文件清理**：`removeStoredFile()` 有路径白名单——必须落在 `<dataDir>/attachments` 之下（`resolve` + `startsWith(root + sep)`），否则拒绝，`store.ts:302-314`；删除失败不报错（`catch` 返回 false，`store.ts:310-313`）。
- **两道确认闸门**：路由要求 `?confirm=true`；接口层还先查 session 是否存在：`server.ts:503-513`。
- **笔记块的删除是软删，不是真删**：`deleteBlock` 设 `deleted_by_user = 1, edited_by_user = 1`，`notes.ts:737-742`；行永远留着。
- **附件删除受保护**：被对话引用过（`turn_meta.attachment_ids_json LIKE`）、被笔记引用过、或已是 `resource_node_id` 时抛 409 拒绝，`attachments.ts:224-231`。

### 5.2 FTS 索引的孤儿行（实证缺口）

- `search_fts` 只有这些触发器：`search_turn_insert`（`db.ts:185`）、`search_node_insert`（`188`）、`search_node_update`（`191`）、`search_note_insert`（`195`）、`search_note_update`（`198`）、`search_note_delete`（`202`）、`search_note_hide`（`205`）、`search_chunk_insert`（`209`）、`search_chunk_delete`（`212`）。

## 附：一句话总结现状

历史记录目前是一个**"能看、能改名、能单人归档、能带预演地硬删"**的最小管理集：
数据模型上把「归档」做成了可逆标记（`sessions.archived_at`），把「删除」做成了事务化硬删 + 磁盘孤儿清理；
但**没有任何回收站、撤销、批量、时间/主题筛选、分页、存储统计、主题级管理**，
列表被硬顶在 50 场（左栏 5 条）且筛选只在内存里做标题子串匹配，
搜索索引还存在 turn/node 删除不清理的孤儿行问题。
