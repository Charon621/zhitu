## 二、你现在可以直接做的事

**安装包在：**

```
zhitu\release\织图-安装包-0.11.1.exe
```

按 `README.md` 的「更新约定」**先卸旧版、再装新版**，双击安装时 Windows 可能提示"已保护你的电脑"，
点「更多信息」→「仍要运行」。装完照 `docs\使用说明.md` 走完两步向导，
填上你自己的 DeepSeek 密钥，在开始卡片上选一个起点。
`release\` 只是构建输出，不要把里面的免安装副本当成日常用的程序（原因见 README「更新约定」）。

**注意：软件能聊天、保存对话、自动记笔记、导入资料、整理未收线、查看笔记页和地图，也能复习、搜索与导出；历史记录支持改名、归档、移入回收站与彻底删除；资料库能导入文档和书籍，并生成人物关系与剧情图谱。** 文字 PDF 按页提取，扫描页和图片需主动开启视觉识别。已引用的资料原件受保护。

## 四、我做了哪些决定，为什么

这些是第 0 步里定下来的，后面所有功能都建立在这上面。

### 1. 界面不直接读数据库，而是通过一个本地服务

软件启动时会在 `127.0.0.1` 上开一个**随机端口**的小服务，界面通过它拿数据。
每次启动的端口和凭证都不一样，本机上别的程序碰不到。

**好处**：以后如果想换一种技术做界面（比如换 Tauri 让安装包从 98MB 变成 20MB），
后端几乎不用改。

### 2. 对话记录只增不改，笔记是"推导"出来的

数据库里的对话流水是"原件"，**永远不修改**。以后所有的笔记、地图，都是从原件推导出来的。

**好处**：将来 AI 整理出错了、或者你换了更好的模型想重新整理历史，随时能重算，
不会破坏原始记录。这是第 1 步能安全推进的前提。

### 3. 两张表管"两种线"

建表的时候就把边分成了四种：`parent`（从哪来）、`prereq`（要先会）、`related`（相关）、`answers`（回答了）。

**为什么现在就分**：方案书里说过，"从哪来"和"要先会"必须分开，这是产品最大的区别点。
建表时不分，以后改结构会很痛。

### 4. 所有 AI 服务商走同一套协议

代码里只有一套调用逻辑，加一家新服务商 = 改一行配置。

### 5. 密钥加密存储

用 Windows 系统自带的加密功能（DPAPI）加密后才写到硬盘上。
如果哪天系统不支持，会退回明文存储，**并且界面会如实提醒用户**，不偷偷摸摸。

### 6. 数据放在用户目录，不放安装目录

`C:\Users\你\AppData\Roaming\zhitu`。放安装目录的话，卸载会删数据，而且系统盘那个位置本来也不让写。

## 五、过程中踩到并解决的坑

这些坑如果不解决，第 1 步开始就会一直卡：

| 坑 | 现象 | 怎么解决的 |
|---|---|---|
| **npm 12 默认禁止安装脚本** | `npm install` 之后 Electron 没有可执行文件，报 "failed to install correctly" | 在 `package.json` 里显式放行；`scripts/postinstall.cjs` 会自动检查并补救 |
| **Electron 从 GitHub 下载断在半路** | 卡在 21.5MB 不动 | 走国内镜像。实测 7 秒下完 130MB |
| **没有 Visual Studio 编译工具** | 担心原生模块编译不了 | 验证发现 `better-sqlite3` 的预编译文件是 N-API 格式，**Node 和 Electron 通用，根本不用编译** |
| **打包时仍想重新编译原生模块** | 报 "Could not find any Visual Studio installation" | 在打包配置里关掉重建步骤（`npmRebuild: false`），直接用预编译文件 |
| **单实例锁导致脚本误判成功** | 第二次启动进程会自己退出，**退出码是 0** | 验证脚本改成以"检查项数量"为准，不只信退出码 |
| **PowerShell 5.1 按 ANSI 读脚本** | 脚本里的中文变乱码，导致语法错误 | 验证脚本改成纯 ASCII |
| **GBK 控制台让验证脚本数不出检查项** | PowerShell 按控制台代码页（中文系统默认 GBK）解码 Node 的输出，`✓` 变成乱码，脚本数出 0 项而误报失败——检查其实全过了，是"假失败" | verify.ps1 开头强制 `[Console]::OutputEncoding` 为 UTF-8（2026-10-01 修） |
| **界面排版超出窗口** | 向导第一步的卡片比窗口还高，顶部被切掉 | 截图发现后压缩了间距，现在卡片 671px，窗口 801px |
| **版本号显示错** | 设置里显示 v38.8.6（那是 Electron 的版本） | 改成读 `package.json` 里的版本号 |
| **安装时不问路径，用户找不到装到哪了** | 用一键安装模式，双击即装、装到隐藏的 AppData 目录 | 改成向导模式（`oneClick: false` + `allowToChangeInstallationDirectory: true`），安装时让用户自己选目录，并保留桌面/开始菜单快捷方式 |
| **同一台机器装到第二个目录，卸载会连坐** | 做安装测试时把用户原本那份也卸载了 | 这是 electron-builder 的固有行为（卸载注册项只有一个）。已写进 README，做安装测试前要先看清楚 |
| **验证脚本把用户的真实数据清空了（严重）** | 验证要反复"清空数据库再重启"，而脚本用的是 `%APPDATA%\zhitu` 这个真实目录，导致用户的向导配置、密钥、对话记录全部被冲掉，且不可恢复 | 应用新增 `ZHITU_DATA_DIR` 环境变量，验证脚本一律跑在 `%TEMP%\zhitu-verify-data` 沙箱里；同时加了两条断言，一旦发现脚本运行在真实目录上就立刻失败。每次跑完还会对比真实数据库的哈希，证明没被碰过 |
| **"当前知识点"跟着主题走，不跟着场次走（v0.9.2 修）** | 一个主题下开了好几场学习，回到旧场次继续问，AI 却把另一场最近碰过的知识点当成"现在聊到哪了"；对某一场点"今天到这儿"，别的场次的未收线问题被算进本场小结，还会把已经收过线的旧场次重新标成未收线 | 把"哪个节点属于哪一场"收敛成 `Store` 里的一个判定，工作集、归航、笔记三处共用。验证里加了三项专门守这条线，修复前每一项都会失败 |
| **删空节点把学习路径一起带走了（v0.9.2 修）** | 重算会把笔记搬到新卡片上，中间那些旧节点就空了；删掉它们时 `ON DELETE CASCADE` 把两端的父边一并删掉，本场路径整段消失，地图上只剩几个孤点 | 重算收尾时先删空节点，再按本场实际轮次顺序重连父边。顺序反过来就会把刚连好的边再删掉——这个坑踩过一次，写进注释了 |
