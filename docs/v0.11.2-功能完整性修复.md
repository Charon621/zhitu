# v0.11.2 功能完整性修复

这次修复针对 2026-10-09 检查确认的七个问题。正式数据和真实模型效果仍需与隔离工程验收分开判断。

| 问题 | 新的使用方式 |
| --- | --- |
| 校对原文没有进入聊天 | 在资料库保存校对后，带着资料聊会优先使用校对后的切片。原件和旧引用仍保留；重新整理才更新分类笔记与人物剧情。 |
| 只有备份导出 | 左栏「导出」→「选择备份文件」→核对预览→「保存快照并恢复这份备份」。 |
| 旧记录只能管理最近 50 场 | 学习记录按标题查找全部记录，每页 25 场，可翻到最早记录。侧栏仍只展示最近五场。 |
| 资料库整理搜不到 | 全局搜索包含分类、标题、正文、人物介绍、剧情和关系；点击结果打开对应资料并显示原文依据。 |
| 未保存编辑丢失 | 笔记编辑和原文校对分别保存本机草稿，切换资料、页面、完整退出与重启后自动恢复。正式保存和取消会清除对应草稿。 |
| 归档不支持完整管理 | 已归档标签支持同样的全库标题搜索、分页、改名、勾选和批量移入回收站。恢复归档后返回普通记录。 |
| 地图长标题拥挤难读 | 紧凑阅读顺序、中文分行、缩放标签策略；右侧完整标题目录支持搜索与点击定位，选中点突出相关连接。主题加载期间禁止视图切换。 |

## 备份恢复规则

- 支持 `zhitu-backup-v1` 格式、数据库版本 2–10，拒绝更高版本和不完整数据。
- 恢复前校验表结构、SQLite 约束和引用、资料整理结果结构、原件大小与 SHA256。附件仅允许软件自身支持的格式，恢复路径由程序重新生成。
- 原件总量单次最多 300 MB，输入 JSON 最多 420 MB。较大的备份会明确报错，不会部分导入。
- 恢复采用合并：所有学习记录获得新的 ID，关联引用同时重新绑定；相同概念字典名称复用已有概念。当前数据、AI 配置、API 密钥和当前学习画像保留。
- 同一备份重复恢复会新增副本。恢复预览会明确说明这一点。
- 恢复前完整 JSON 和 SQLite 快照写入当前数据目录 `backups/<时间戳-标识>/`。完整 JSON 不包含 API 密钥；SQLite 是本机工作台快照，留在本机。
- 当前已有原件丢失时，保存数据库、其余原件和明确的缺失清单后，仍可恢复备份中的完整副本；成功提示会说明原件缺失情况。
- 数据插入和索引更新在同一事务内完成，失败时回滚数据库并清理本次新建的原件。
- 回收站记录重新获得 30 天保留期。未结束场次以已收线状态恢复，继续聊天可重新打开；正在运行的资料整理恢复为待重试，需手动继续。恢复不会自动发起模型请求。
- 成功后点击「完成并重新加载」刷新工作台。

## 草稿与来源

草稿保存在本机应用存储中，按附件分开；两种编辑可以同时存在。草稿还不是正式笔记，因此全局搜索、聊天和导出使用正式保存的内容。草稿不包含在全部数据 JSON 中；重要修改应先保存再备份。若本机草稿保存失败，界面明确提示并提供草稿导出，切换资料、离开页面或关闭应用前会提醒。

旧原文切片保留以供历史引用读取；新检索只读取活动原文版本。校对图片后，聊天以校对文字为依据，避免旧图像识别内容覆盖手动校对；查看原件仍显示原始图片。

## 验证与更新

`npm run typecheck`、`npm run build`、`scripts/verify.ps1`、`npm run test:history`、`npm run test:library` 和 `npm run test:completeness` 是回归入口。新增 Electron 界面验收见 `scripts/completeness-ui.cjs`，完整退出重启见 `scripts/draft-restart.cjs`。这些脚本只使用临时数据目录、合成资料和本机测试模型。

本次不改动真实用户数据，也不自动替换已安装软件。运行 v0.11.2 安装包后才会更新安装版；首次打开会将数据库迁移到 v10，旧版本不能读取迁移后的数据库。源码回退快照位于本次交付目录，需要数据回退时使用迁移前的数据副本，勿用旧版直接打开新版库。
