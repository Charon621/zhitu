# 织图 · 提示词说明

> 这个文件记录"我们到底给 AI 下过什么指令"，以及为什么。
> 提示词是这个软件真正的核心，界面只是外壳。

---

## 一、现在用的提示词（v0.8.1）

每次发消息时，这段文字会作为系统指令发给 AI。不再询问学习者水平，也不把旧设置里的 `learnerLevel` 拼进去。

原文在 `src\main\core\prompts.ts` 的 `SYSTEM_PROMPT`，排版约束抽成了共享的 `FORMAT_RULES`：

```
你是"织图"里的学习助手，陪一个自学者从零开始探索一个领域。

怎么说话：用中文，口语化，像一个懂行的朋友在聊天，不要像教科书。一次只讲清楚一件事，
不要一口气倒出一大堆。少用术语，非用不可的时候先用一句大白话把它解释清楚。
回答控制在 200 字以内，除非对方明确要求展开。

怎么排版（这是硬要求，必须遵守）：把话写成连贯的段落，绝对不要用"•"、"-"、"*"
这类符号开头的列表，一个都不要用。要分几点讲的时候，就用"第一……然后……最后……"
这样的话把它们连起来，而不是另起一行打符号。只有真正的操作步骤或者配置清单才编号，
用"1. 2. 3."。不要客套开场，也不要说"作为AI""很高兴为您服务""希望以上回答对您有帮助"
这类套话，直接说内容。

怎么教：对方问什么就先答什么，别急着把它扩展成一门课。答完之后可以顺带提一句
"要不要先看看某某"，但一次最多提一个，提完就不要追着问。不要主动把话题拉回"主线"，
对方想跑偏就陪他跑偏，跑偏是他的权利。如果对方理解错了，直接指出来，不要顺着说。
```

另外，模型请求由工作集装配：主题和目标、当前知识点与最多五层来路、相关旧知识、最多十条笔记标题、最多三段相关资料，以及最近八轮完整对话。文本上下文按六千 token 的保守估算控制；单条输入超过容量会明确提示，原话仍保留在本场记录中。对话温度是 0.7。

开始卡片增加了一条独立提示词 `START_ENTRIES_PROMPT`，同样拼入 `FORMAT_RULES`。用户输入领域并选择“偏原理”“偏动手”或“随便看看”后，它只返回三个具体问题和每个问题的一句理由，不生成整份大纲。每个理由不超过 30 字。该请求优先使用 `utilityModel`，未配置时回退到对话模型；用户点了某个问题后才创建主题并发起第一轮对话。

第 1 步增加 `NOTE_EXTRACT_PROMPT`，把一轮助手回答压缩成最多三条有实指的笔记块，输入中带当前节点已有笔记和本场最近笔记。模型必须说明丢弃了什么，不能把重复、元话语、无依据经验数字写进卡片。随后 `NOTE_VERIFY_PROMPT` 独立核对候选块与本场旧笔记能否同时成立；有冲突就拒绝候选断言，核对失败则不写入新笔记。两条提示词都复用 `FORMAT_RULES`。这道额外核对由产品经理明确选择“优先保证笔记质量”，代价是多一次后台模型请求。

第 2 步增加 `DOCUMENT_CONTEXT_PROMPT`，只允许模型根据本轮检索到的资料切片和明确附上的页面图片回答；PDF 与 PPT 要标真实页码，没有证据要直说。扫描 PDF 的页面图片可由视觉模型转录成带页码的切片，`OCR_PROMPT` 要求只抄可辨文字，不猜缺失字词。两条新提示词都复用 `FORMAT_RULES`，自动化验证分别检查六项排版约束。视觉转录可能出错，来源卡片会提示回看原件。

第 3 步增加 `HOMEWARD_PROMPT`，用本场未收线的原问题、祖先路径、笔记与最近对话判断是否真的讲清。没有明确回答时保留未收线，并从最近尚未弄懂的停靠点提出下一步问题。它同样复用 `FORMAT_RULES`。真实 DeepSeek 测试第一轮正确判为未收线，但下一步跳回最初问题；加强「从停靠点继续」要求后单项复测通过。模型输出仍需更多真实学习场景检验。

第 6 步增加 `REVIEW_QUESTION_PROMPT` 和 `REVIEW_GRADE_PROMPT`。前者根据笔记出一道应用题，禁止问定义或复述；后者对照笔记、题目和学习者答案给出具体反馈及掌握度变化。两条提示词都复用 `FORMAT_RULES`，本地自动化检查排版和完整出题、判题链路。真实 DeepSeek 各测试一次，两项均通过；这是少量样本，仍需在长期学习中观察。

第 7 步增加 `PROFILE_SIGNAL_PROMPT`，每轮只标记能从提问中看见的信号，拿不准时不标。分数与置信度由程序按规格计算；置信度大于 0.5 时才在对话提示词中加入一句深度提示。用户也能在设置中手动选择少解释、适中或多解释。两种典型信号用真实 DeepSeek 各测一次，通过；长期推断的准确性仍需真实使用检验。对话模式只在共享 `SYSTEM_PROMPT` 末尾追加引导或自由说明，工作集把主题、知识路径、相关旧笔记和最近八轮装入上下文。

## 二、v0.1.0 是什么样，为什么要改

第一版是这么写的：

```
说话方式：
- 用中文，口语化，像一个懂行的朋友在聊天，不要像教科书。
- 一次讲清楚一件事，不要一口气倒出一大堆。
...
```

你的反馈是"非常机械化"。这个判断是准确的，原因很具体：

**那八条里，每一条都在讲"怎么说话"，没有一条在讲"怎么教"。** "口语化""少用术语""200 字以内"是语气约束；"别扩展成课程""别拉回主线"是禁止项。唯一算教学动作的只有"顺带提一句要不要先看看某某"。

结果就是它被写成了一个「好的客服」，不是「好的老师」：你问什么它答什么，答得利索，但它不会反问你、不会试探你懂没懂、不会在你卡住时换个角度讲。

还有一层原因：**它不知道你在哪**。没有学习目标、没有你已经学过什么、没有当前停在哪个节点。没有任何上下文，它只能就事论事地回答这一句。

## 三、v0.1.1 改了什么

只加了一节"怎么排版"，就是你提的三条要求。**教学方式那一节我没动**，因为你说"你觉得要修改的可以改"，但也说了要先问清楚"机械"具体指哪种——那个问题你还没回答，我不想凭猜测大改。

新增的三条要求落进了两处：一是提示词正文里明确写死，二是 `scripts/e2e.cjs` 里加了断言，检查这段文字真的被发出去了。v0.1.2 的领域入口提示词也复用了它，并有独立断言。这样以后改提示词时把这些要求弄丢，验证会失败。

还有一个细节：**提示词自己也不能用符号列表**，否则等于在给 AI 做反面示范。这条也写成了断言。

## 四、下一步打算怎么改

等你回答"机械"是指哪一种之后，我准备把"怎么教"那一节整个重写。草稿方向是这样：

```
你的工作不是回答问题，是让这个人自己把这件事想明白。

每一轮里，你要做三件事中的一件（自己判断该做哪件）：
他卡住了就换一个角度讲，换角度优先于再讲一遍；
他好像懂了就追一个具体的小问题验证一下，答对了才算懂；
他问的东西太大了就先反问他一句，把范围缩到一个能立刻讲清的点。

判断他懂没懂，看他的用词：
复述你的原话，大概率没懂，换个说法再来；
用自己的例子讲出来，懂了，可以往下走；
问出了你没提到的角度，是真懂了，跟住他的方向。
```

关键差别是：旧版每句话都在限制"怎么说"，新版每句话都在决定"做什么"。

**但这一版有个前提**：它需要知道"上一句他说了什么、他懂到哪了"。这就要等第 1 步把每轮的知识点和掌握度记下来之后，才能真的起作用。所以提示词改进和第 1 步是绑在一起的，分不开。

## 五、怎么验证提示词真的生效

自动化测试只能证明"提示词发出去了"，证明不了"模型照着做了"。所以另有一个需要联网的检查：

```bash
npm run prompt-check
```

它会向真实 DeepSeek 发三个对话问题，再试领域入口、笔记抽取和冲突核对提示词。**这会产生 API 费用，日常自动化验证不会运行它。** 脚本现在由 Electron 启动，只读本机数据库，并在主进程内解开 Windows 加密的密钥；不会把密钥写进报告或传给界面。报告会显示接口返回的 token 用量，具体扣费以服务商账单为准。

如果发现模型不听话（比如还是爱打列表），说明提示词的约束力不够，要把那条要求写得更强硬、更靠前，或者给出正反例。
